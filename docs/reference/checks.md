# Checks

> Reference · [Documentation](../../README.md#documentation)

What `gitops-check` reports on the "after" rendering. How a run gets there:
[How it works](../explanation/how-it-works.md).

## Errors (block the merge)

- an Application or ApplicationSet that doesn't render: Argo CD's own
  error (bad path, chart version, kustomize error, unknown revision);
- a resource rendered by two Applications (identity: group/kind,
  namespace, name; a resource without a namespace takes its Application's
  destination namespace, unless its kind is cluster-scoped);
- a Secret with values in clear **in the Git tree** (no `sops:` block), or
  a kustomize `secretGenerator`; Argo CD repository and cluster Secrets
  without credential keys are exempt;
- a resource invalid against its schema (kubeconform: Kubernetes' schemas
  and the CRD catalog);
- a directory with manifests that no entry point reaches (unless listed
  under `ignore`); an Application's source directory counts as reached,
  and everything below it when it is a Helm chart or has
  `directory.recurse`, and the kustomize components the Application adds;
- what Argo CD would refuse at sync: an Application whose source,
  destination, resource kind (cluster-scoped or namespaced) or resource
  namespace its AppProject doesn't permit, or whose project doesn't exist.
  The preview renders everything in `default`, so the AppProjects of the
  rendering itself (namespace `argocd`) are the reference; Applications of
  other Argo CD instances and of undeployed entry points aren't checked;
- a pull request not up to date with its target.

## Warnings (reported only)

Files generated by `deploy-talos.py` edited by hand, the
target branch itself failing to render, an ApplicationSet generating
nothing, resources without a known schema.

## Diff statuses

Each Application in the report is **added**, **removed**, **changed**,
**failed** (doesn't render after) or **repaired** (didn't render before).
